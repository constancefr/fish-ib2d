<h2> Constance's additions </h2>

I have added my own example to this fork to simulate a hardware platform I am working on: `pyIB2d/Examples/FinRay`. Everything else (other examples, IB2d driver code) is untouched and kept as in the original IB2d repository.

To generate sims, run:
1. `run_case.py`: a simple script to automate simulations over a range of predefined cases (sweep over parameter combinations) via subprocesses. It calls `FinRay_Geom.py` then `main2d.py` for each case. Run in terminal with `python run_case.py`.

2. `make_movie.py`: a script to automate video generation of simulations from the result `.vtk` files generated when calling `main2d.py`. This avoids having to manually adjust parameters in VisIt's GUI (super tedious). Example run in terminal, for some case `amp0.010_E7.40e+05` currently generated by `run_case.py`: `/Applications/VisIt.app/Contents/Resources/bin/visit -quiet -cli -nowin -s make_movie.py -- results/amp0.010_E7.40e+05 output_sim.mp4`.

Utils:
- `FinRay_Geom.py`: creates the Lagrangian structure of the FinRay tail, writing to the necessary input files for the simulation (.vertex, .spring, .target, etc.). Change this file to modify add or modify fiber models - see the 2017 IB2d paper, Sections 2.1 (Fiber models) and 3 (Workflow).

- `main2d.py`: runs the actual immersed boundary simulation (fetches parameters from `input2d` and calls IB2d's driver located in the `IBM_Blackbox`). Can run this manually instead of `run_case.py` if a parameter sweep is not needed.

- `update_Target_Point_Positions.py`: called by IB2d's driver at each timestep to implement the actuation via target points defined in `FinRay_Geom.py`. Modify this to change the actuation.

Make sure you have downloaded <a href="https://visit-dav.github.io/visit-website/releases-as-tables/#latest">VisIt</a> for the movie generation to work!

A second example, `pyIB2d/Examples/NACA0020_Wing`, replicates the NACA0020 wing of the WaterLily_FSI two-way-coupling example (`Wing_3order.jl`): a rigid leading edge plus a flexible Euler-Bernoulli cantilever (E = 1e4 Pa) in a free stream whose angle of attack switches 0 -> 15 deg. See its `NOTES.md` for the GVS -> IB2d mapping, the calibration (`verify_structure.py`), and the known limitations (notably: the stock IB2d `.beam` force is not conservative, so bending is done through `user_force_model`; and Re is reduced for solver stability). Run `python Wing_Geom.py`, then `python main2d.py`, then `python analyze_run.py` from that folder.
